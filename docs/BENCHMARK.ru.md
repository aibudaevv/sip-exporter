# Нагрузочные тесты с RTP

[English](BENCHMARK.md)

Публичные результаты benchmark публикуются только для того же неизменяемого релизного образа,
который пользователь может скачать по инструкции установки. Результаты образов разработки
остаются во внутренних инженерных записях и не выдаются за производительность релиза.

## Результаты релиза ещё не получены

Текущий релизный образ ещё не измерен финальным RTP-профилем. Поэтому эта страница пока не
устанавливает поддерживаемый предел CPS и не публикует измерения другой сборки.

После сборки релизного образа из `develop` его нужно последовательно проверить на 10, 30, 50 и
80 CPS: полные SIP-вызовы, двусторонний PCMA RTP, интервал пакетов 20 мс и 18 секунд медиа на
вызов. Для каждого публикуемого результата необходимо зафиксировать:

- неизменяемый digest образа и ревизию исходного кода;
- фактический CPS, RTP p95, CPU p95 и working-set p99;
- ошибки и повторные передачи генератора;
- точность захвата SIP, SER, ошибки экспортёра, отбрасывания RTP в userspace и потери сокета ядра;
- ожидаемое и наблюдаемое число RTP-пакетов, а также потери по sequence, дубликаты и нарушение порядка;
- хост, лимиты контейнера, топологию захвата, опциональные лейблы и длительность теста.

Точка может получить PASS только после успешного завершения проверок генератора и целостности.
Один короткий успешный прогон не устанавливает устойчивую production-ёмкость; для такого вывода
нужны повторные прогоны и более длительный soak-тест.

Нагрузочные тесты нельзя запускать одновременно с E2E и другими RTP-тестами: они используют
общие ресурсы захвата. Укажите новый абсолютный каталог артефактов и неизменяемый релизный тег:

```bash
make version=<release-tag> \
  ARTIFACT_DIR=/absolute/path/to/new-artifact-directory \
  test-load-targeted TEST='^TestLoadFullCallWithRTP$'
```

Не увеличивайте очереди экспортёра и не ослабляйте проверки ради PASS. Перед публикацией
проверьте каждый сценарий ResultV2, CSV генератора, метрики до/после и выборки ресурсов.
